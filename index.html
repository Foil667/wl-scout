HOW VERDICTS WORK

ELIGIBLE — holder gate proven onchain (e.g. you hold a CCFF00 square). A verified fact.

NOT ELIGIBLE / INELIGIBLE_BY_GATE — onchain proof you don't meet the gate (e.g. needs 4 squares, you hold 1).

CHECKER — an offchain allowlist phase exists; only the project's own checker/API knows membership. The app links it and never fakes green.

UNKNOWN — phase metadata known but no checker route, or a data leg failed.

Onchain legs: SeaDrop getPublicDrop (0xbc6a629c) + allowListMerkleRoot (0x32bf11f5) on canonical + RH fork, holder gates via balanceOf (0x70a08231) / ownerOf (0x6352211e). OpenSea API leg is dropped in this static build (no API key ships in client code) — onchain legs carry the verdicts.
